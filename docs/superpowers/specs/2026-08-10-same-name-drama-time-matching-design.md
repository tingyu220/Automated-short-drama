# 同名剧分钟级防误选设计

## 1. 目标与范围

番茄平台按剧名搜索出现多条同名记录时，以飞书剧目表中的剧名和时间作为唯一匹配依据，禁止默认选择首条结果或按最近时间猜测。

本设计只调整番茄 IAA/IAP 链接提取前的剧目选择，不改变链接价格区间、选集、回填、账户分配和投放规则。

## 2. 唯一匹配规则

- 匹配键为：`标准化剧名 + 上海时区时间（YYYY-MM-DD HH:mm）`。
- 飞书任务时间与番茄候选时间统一转换为上海时区后截断秒和微秒。
- 搜索结果必须同时满足剧名一致、分钟一致。
- 业务保证同一时刻不会存在两部同名剧，但系统仍必须防御零匹配和多匹配。
- 禁止使用最近时间、第一条结果、页面顺序或模糊剧名作为兜底选择。

## 3. 两阶段校验流程

### 3.1 列表页选择

Page Object 读取全部同名候选，返回平台无关候选数据：

- 标准化前剧名；
- 平台展示时间；
- 稳定的页面定位标识；
- 页面顺序（仅用于日志，不参与选择）。

Domain 匹配器按唯一匹配键筛选：

- 唯一命中：允许打开对应详情；
- 零命中：停止并转人工；
- 多命中：停止并转人工。

### 3.2 详情页复核

打开唯一候选后，再读取详情页剧名和时间，并使用相同规则复核。只有详情页仍唯一一致时，才允许继续生成 IAA/IAP 链接。

详情页缺字段、格式无法解析或数据不一致时，禁止点击生成链接并转人工。

## 4. 模块边界

- Domain：新增纯函数匹配器，负责剧名标准化、上海时区分钟归一化和唯一性判断；不依赖 Playwright。
- Application：把任务的 `drama_name`、`available_time` 传给 Tomato Adapter，并把匹配失败映射为任务人工处理。
- Adapter：编排列表读取、领域匹配、详情复核；不决定近似匹配策略。
- Page Object：只读取候选和详情字段、按稳定标识打开详情，不更新任务状态。
- Selectors：列表剧名、列表时间、详情剧名和详情时间均放入 JSON 配置。

IAA 与 IAP 必须复用同一匹配器和候选模型，禁止各自实现一套同名剧规则。

## 5. 状态与审计

匹配失败统一产生：

- `link_status = DRAMA_MISMATCH`；
- 任务状态进入 `MANUAL_REVIEW`；
- 记录任务剧名、任务分钟、候选剧名/分钟、候选数量和失败阶段；
- 保存当前页面截图；
- 不生成链接、不回填飞书、不继续账户分配。

时间解析异常不得降级为近似匹配，按 `DRAMA_MISMATCH` 处理并保留原始时间文本。

## 6. 测试要求

单元测试覆盖：

- 唯一同名同分钟命中；
- 同名不同分钟不命中；
- 秒和微秒被忽略；
- UTC 与上海时区正确归一化；
- 零匹配和多匹配均失败；
- 剧名标准化后匹配；
- 时间格式无法解析时失败。

Page Object/Adapter 测试覆盖：

- 按稳定标识打开唯一候选，而非默认首条；
- 详情复核成功后才调用生成链接；
- 详情剧名或分钟不一致时生成按钮零调用；
- IAA 与 IAP 共用相同选择逻辑。

集成测试覆盖：匹配失败后任务进入 `MANUAL_REVIEW`，链接不回填，后续投放步骤不执行。

## 7. 验收标准

- 同名不同分钟的候选不会被误选。
- 唯一的同名同分钟候选通过列表和详情两次校验后可继续。
- 任意不确定结果均停止并人工处理，无自动猜测路径。
- 现有非同名剧、IAA/IAP 价格和选集规则保持不变。
