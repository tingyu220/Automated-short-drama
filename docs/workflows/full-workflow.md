# 短剧投放全流程自动化工作台：端到端全流程文档

> 生成时间：2026-08-06 | 版本：V1

本文档描述短剧投放全流程自动化工作台 V1 的完整执行流程、状态机与异常处理规则，作为 Phase 0 的全流程基线文档。本文档与设计文档、系统架构文档保持一致，后续实现以本文档为执行依据。

## 当前运行终点（2026-08-16）

当前 Worker 只运行到链接准备终点，支持两种终点：

- `LINK_EXTRACTION`：剧目上线后提取并冻结 IAA/2.9/9.9 链接，回填飞书 J/K/L；
- `LINK_READY`（默认）：在上述基础上，投放系统先复用或创建剧目，再复用或创建每条有效链接对应的推广内容。

番茄已存在链接必须按漫剧名与选集/模板搜索、点击查看后复用；未命中才允许创建。当前终点不执行账户、素材、PlanSpec、计划提交、轮询或 M=1 回写。

## 当日剧目导入（2026-08-17）

公用表只作为当天剧目的只读来源。Dashboard 的“读取今日剧目”按北京时间生成预览；E 列原样复制，行序与公用表一致。用户确认后，新增行一次性插入私有表第 2 行，旧行下移并回读校验。后续扫描、提链和搭建只读取私有表。

## 1. 运行形态

- 系统包含 Control Server 与 Automation Worker，V1 固定单 Worker；
- 平台写操作由 Worker 单线程串行执行；
- 所有动态业务参数从已发布规则版本与任务执行时的配置快照读取；
- 默认 `ALLOW_FINAL_SUBMIT=false`，真实提交需人工开启；
- Dry Run / Mock 阶段只执行流程编排，不污染飞书表，不真提交，不写完成标记。

## 2. 主流程

主流程按以下顺序执行，每一步完成后写入 `StepRun` 并记录执行事件：

1. **00:00 全量扫描**：每天 00:00 扫描私有飞书剧目表当天全部任务，按稳定 `source_key` 去重；`sheet_row` 只用于 J/K/L/M 实际回填；
2. **应用启动即时扫描**：应用启动时立即扫描一次当天任务，只补录缺失项，不重复创建已有任务；
3. **每小时增量扫描**：每小时扫描一次，补录当天新增行，同一任务不会重复入队；
4. **等待 WAITING_TIME**：任务保持 `WAITING_TIME` 状态，等待 E 列投放时间到达；时间未到不打开番茄、不搜索、不占页面；
5. **到点入队**：到达投放时间后任务流转为 `READY → QUEUED`，等待 Worker 领取；
6. **到点链接准备并冻结**：Worker 领取任务后按 H 列平台分流，准备动作只执行一次：
   - 番茄：搜索剧目，按“标准化剧名 + 上海时区分钟”从列表唯一选择并在详情二次复核；成功后免费入口提取 IAA 链接，付费入口扫描模板提取 9.9/2.9 链接；
   - 剧变：直接读取表内已有 J/K/L 链接，不进入番茄，不构造链接，空值表示该类型链接不存在；
7. **链接回填与快照消费**：番茄提取成功后回填 J/K/L；剧变只读取原值。随后冻结 `link_set`，账户与投放步骤只消费该快照，不再次进入番茄；
8. **链接就绪终点（当前启用）**：投放系统按剧名复用或创建剧目资源，再复用或创建 IAA/2.9/9.9 推广内容；任务标记 `LINK_READY` 并结束本次队列。
9. **账户块分配（后续阶段）**：读取飞书 iaa/iap 账户表最新数据，从上向下找第一个完整可用块并整块回填剧名，回读确认；
10. **生成 PlanSpec（后续阶段）**：取账户、CID、推广内容、命名模板生成标准投放计划规格并校验；
11. **提交（后续阶段）**：仅当 `ALLOW_FINAL_SUBMIT=true` 时提交标准投放计划，否则停在“填写但不提交”；
12. **轮询（后续阶段）**：每 5 分钟轮询投放系统/巨量引擎 V2 任务状态，最长 2 小时；
13. **M=1（后续阶段）**：状态=已完成且确认为真实提交后，回写飞书 M 列 `1`，N 列由表内机制自动变 `OK`；
14. **清活动记录留台账（后续阶段）**：清理活动队列项与运行资源，保留 `TaskLedger`、执行日志与产物。

## 3. 任务状态机

```text
WAITING_TIME → READY → QUEUED → RUNNING
                                    ├→ COMPLETED
                                    ├→ MANUAL_REVIEW
                                    └→ FAILED / CANCELLED
```

队列状态支持：`WAITING_TIME / QUEUED / CLAIMED / RUNNING / RETRY_WAIT / PAUSED / MANUAL_REVIEW / COMPLETED / CANCELLED`。

Worker 领取后进入 `CLAIMED/RUNNING`，持续心跳；崩溃后由租约过期恢复，任务重新可领取。

## 4. 异常分支

### 4.1 MANUAL_REVIEW

以下情况进入 `MANUAL_REVIEW` 并在异常中心记录本地原因与截图：

- 失败、部分失败、超时；
- 链接与主剧不匹配（停止、截图，禁止自动换主剧/换剧名）；
- 同名剧列表零匹配、多匹配、时间无法解析或详情分钟复核失败；禁止选择第一条或最近时间；
- IAP 同时有 9.9 和 2.9 时只找到一组，不做部分分配；
- 账户块只有部分行空白或回读确认失败；
- 写入飞书前回读发现目标行已有非空剧名。

人工处理后任务可重试或取消，重试次数计入队列项。

### 4.2 重试

- 可重试失败默认重试 3 次，重试前进入 `RETRY_WAIT`；
- 创建类操作重试前必须先对账，确认外部平台不存在目标资源才允许重试；
- 飞书表已写入且回读确认成功的步骤不重复执行。

### 4.3 超时

- 任何创建/提交操作超时或结果不明确，一律视为 `RESULT_UNCERTAIN`；
- 轮询超时（超过 2 小时）进入 `MANUAL_REVIEW`，保留全部中间产物供人工核查；
- 超时后禁止直接重复点击创建或提交。

### 4.4 部分写入

- 飞书账户块或链接回填只写入部分行时标记 `PARTIAL_WRITE`；
- 部分写入后不继续后续步骤，进入 `MANUAL_REVIEW`；
- 已写入且回读确认的行保留，未写入行不补写，交由人工处理。

### 4.5 RESULT_UNCERTAIN

- 任何创建操作超时或结果不明确时先查询外部平台；
- 找到目标资源则补记成功并继续；
- 确认不存在才允许重试；
- 禁止直接重复提交。

### 4.6 登录失效

- 任一平台登录态失效时暂停该平台全部写操作，任务进入 `MANUAL_REVIEW`；
- 保留截图与异常记录，不自动重登；
- 人工恢复登录态后，任务从断点步骤重试，已确认完成的步骤不重复执行。

## 5. Dry Run 规则

Dry Run / Mock 阶段明确约束：

- 不写飞书剧目表（不回填 J/K/L）；
- 不写飞书账户表（不分配账户块）；
- 不真提交标准投放计划；
- 不写 M=1；
- 外部平台操作全部走 Mock 或只读验证；
- 本地 SQLite 仍记录流程运行、StepRun、链接提取结果与异常，供 Dashboard 查看。

## 6. 上计划执行剧本（已确认）

### 6.1 通用前置

1. 每天先按需将公用表当天剧目确认导入私有表；Worker 只读取私有表，一行剧目生成一个任务，按 E 列北京时间到点入队。
2. 链接准备严格在任务到点领取后执行一次并冻结；后续步骤只读取该任务快照，不重新按临时页面结果选链接。
3. Worker 固定为单浏览器、单标签页、单线程；复用登录态，多个同一时间任务按队列串行执行。
4. 任一步页面结果不明确、素材数量不一致、链接主剧不匹配或登录失效，立即暂停当前任务并进入人工处理；提供“暂停当前任务”和“暂停整个系统”。

### 6.2 端免 IAA

1. 巨量引擎 V2 点击“创投 2.0”，填入 IAA 账户块。
2. 固定选择：创编方式=极速创建、投放方式=标准投放、推广业务=端原生、抖音号=`43242208659`。
3. 开户预设按主体选择；广告预设按 CID 分别选择；平台按剧目平台选择。
4. 推广内容：首个 CID 选择该剧 IAA 链接后点击“批量应用”。商品库不处理。
5. 素材：搜索精确剧名，切换 `300 条/页`，再次搜索确认结果数无误后才允许全选当前页。按素材规则生成素材组。
6. 标题：按标题包分配，批量添加全部 6 个标题包，乱序一次后确认。
7. 叉乘规则：项目规则=按广告数生成，广告规则=按素材组生成，两个平均分配关闭。
8. 任务名称严格使用：`<平台方>#端免<剧名称><日期>bxr-<创建日期>-<时分秒-n>`。
9. 端免出现“商品名称和剧名称不一致”红色提示时，停止提交并进入人工处理。

### 6.3 端付 IAP

1. 使用 IAP 账户块，固定字段与通用前置一致。
2. 开户预设使用对应主体预设；广告预设按 CID 选择。
3. 推广内容按 CID 使用对应价格链接：B1 使用 9.9 链接，B2 使用 2.9 链接。商品库不处理。
4. 素材、标题和叉乘配置遵循通用规则。
5. 任务名称严格使用：`<平台方>#端付<剧名称><日期>ubr-<创建日期>-<时分秒-n>`。
6. 端付出现“商品名称和剧名称不一致”提示属于正常现象，记录即可，不阻断提交。

## 7. 幂等与一致性

- 剧目行以稳定 `source_key` 去重；顶部插行后同步最新 `sheet_row`；
- 链接以 `task_id + link_type + url_hash` 去重；
- 创建类操作超时先对账，禁止直接重复提交；
- 飞书写入前重新读取目标行，非空剧名绝不覆盖；
- 任务完成状态以投放系统巨量引擎 V2 任务页为最终来源，状态=已完成才写 M=1；
- 完成后清理活动队列项，`TaskLedger`、执行日志与截图长期保留。
