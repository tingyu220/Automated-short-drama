# 短剧投放全流程自动化工作台 前端 UI 开发方案 V1.0

> 独立子计划，关联主设计文档：`docs/superpowers/specs/2026-08-06-short-drama-delivery-design.md`

## 1. 设计定位

本系统前端不是展示型官网，也不是传统数据大屏，而是投手、运营人员每天长期使用的自动化工作台。

整体产品定位：

> 企业级投放运营控制台 + 自动化任务指挥中心 + 规则配置中心。

核心目标：

```text
操作效率高
信息层级清楚
任务状态易理解
异常处理路径明确
高风险操作足够安全
界面具有现代感和高级感
长期使用不疲劳
```

设计必须避免两个极端：

### 极端一：传统企业后台

表现为：

```text
灰白页面
默认组件堆叠
大量边框
表格信息拥挤
缺少视觉重点
```

这种设计虽然能用，但会显得廉价、陈旧。

### 极端二：炫技型科技大屏

表现为：

```text
纯黑背景
霓虹渐变
粒子动画
超大数字
复杂发光
大量无效图表
```

这种设计不适合长期工作，也会降低操作效率。

---

# 2. 视觉方案对比

## 方案 A：传统浅色企业后台

特点：

```text
浅色侧边栏
白色内容区
标准表格
标准表单
少量状态颜色
```

优点：

* 熟悉；
* 开发速度快；
* 信息密度高。

缺点：

* 容易做成普通后台模板；
* 自动化任务的运行感不够；
* 高级感较弱。

不作为首选。

---

## 方案 B：深色自动化指挥中心

特点：

```text
全局深色
高亮状态轨道
大面积运行指标
强视觉动效
```

优点：

* 自动化和科技感强；
* 运行过程醒目；
* 展示效果好。

缺点：

* 表格和配置表单长时间使用容易疲劳；
* 信息密度高时可读性下降；
* 不适合大量规则编辑。

不建议作为整个系统的主题。

---

## 方案 C：混合型企业控制台

这是本项目推荐方案。

结构：

```text
深色侧边导航
+
浅色主工作区
+
蓝紫品牌强调色
+
Bento重点卡片
+
高密度表格
+
轻量微交互
```

这种方式同时具备：

* 企业系统的稳定性；
* 自动化平台的科技感；
* 现代 SaaS 产品的精致度；
* 配置系统的可读性；
* 长时间使用的舒适度。

# 3. 设计参考网站的具体使用方式

前端设计不能只是“参考这些网站”，必须明确每个网站用于解决什么问题。

## 3.1 Detail

用于参考：

```text
按钮状态
表单反馈
保存交互
错误提示
筛选器
登录态提示
空状态
悬停效果
复制操作
```

重点是微交互质量。

例如：

```text
保存
→ 保存中
→ 保存成功
```

不能只是点击后弹出一个普通消息框。

---

## 3.2 Landbook

用于参考：

```text
页面信息层级
标题与操作区布局
模块间留白
内容分区
页面节奏
```

吸收其清晰、现代的结构，但不使用营销落地页的大标题和大面积空白。

---

## 3.3 Awwwards

用于参考：

```text
视觉层次
排版比例
动效节奏
品牌感
页面进入效果
```

只吸收视觉完成度，不使用：

* 实验性导航；
* 大量视差滚动；
* 复杂鼠标跟随；
* 影响效率的过渡。

## 4.3 圆角与阴影

建议：

```text

小卡片圆角：10px
主要面板圆角：12px
弹窗和抽屉圆角：12px
```

阴影应克制：

```text
普通面板：几乎无阴影，以边框区分
浮层：轻微阴影
弹窗：中等阴影
```

禁止所有卡片都使用明显投影。

```text
卡片内边距：20px
```

## 4.5 字体和字号

优先使用：

```text
Inter
PingFang SC
Microsoft YaHei
系统无衬线字体
```

推荐字号：

```text
页面标题：24px
模块标题：18px
卡片标题：15px
正文：14px
表格：13px或14px
辅助信息：12px

```

避免：

* 表格字体过小；
* 页面标题过大；
* 大量粗体；
* 辅助文字对比度过低。

## 7.2 当前运行任务

这是首页视觉权重最高的区域。

```text

```


```text

→ 链接
→ 剧目资源
→ 推广配置
→ 产品库
→ PlanSpec
→ 提交
→ 状态确认
```


# 26. UI 验收标准

前端达到以下要求才算合格：

```text
用户能快速找到当前运行任务
用户能快速发现需要处理的异常
用户能清楚看到任务当前步骤
用户能查询链接来源和流转
用户能查看飞书账户实时状态
用户能安全修改价格和素材规则
用户能在发布规则前看到模拟结果
用户能查看PlanSpec并理解校验失败原因
用户始终知道最终提交是否开启
页面适合长时间工作
界面现代但不过度娱乐化
颜色、间距、组件和交互保持统一
```

最终效果应当体现：

> 这是一套成熟、可靠、现代的企业级自动化运营系统，而不是由默认后台模板和普通表格简单拼接出来的页面。
