# 前端导航、返回键与分页改造计划

## 一、检查结论

- 已有 `AppLayout + AppSidebar + AppTopbar + RouterView`，侧边栏包含 7 个一级入口：工作台、今日任务、自动化队列、计划管理、规则与配置、异常中心、系统记录。
- 问题 1：模块页没有统一的返回键；任务详情、计划预览等抽屉只有关闭按钮，没有明确的“返回列表/返回工作台”导航。
- 问题 2：今日任务、自动化队列、计划管理、异常中心、系统记录均为一次性渲染全部数据，没有分页。
- 问题 3：工作台页承担总览职责，但内容区同时出现任务、队列、异常、Session 等，信息密度高；侧边栏导航存在但用户入口感不足。

## 二、修改方案

### A. 统一页面头部与返回键

- 新增 `PageHeader` 通用组件：
  - 左侧显示页面标题与说明；
  - 非工作台页面显示“返回工作台”按钮；
  - 任务/计划等详情打开时，抽屉顶部显示“返回列表”按钮（或保留关闭按钮并高亮）。
- `AppTopbar` 增加当前页面面包屑：`工作台 / 今日任务` 等，面包屑首页可点击返回。

### B. 分页

- 新增 `PaginationBar` 通用组件（基于 `el-pagination`）：
  - 支持 page/pageSize、total、layout（total/sizes/prev/pager/next/jumper）；
  - 每页可选 10/20/50。
- 接入页面：今日任务、自动化队列、计划管理、异常中心、系统记录。
- 第一期使用前端分页（数据量较小、后端契约稳定后）；后端预留 `page/page_size` 参数，后续切后端分页不改组件。

### C. 工作台精简与侧边栏强化

- 工作台保留：任务总览、当前执行、即将到时间、异常提醒、Worker/Session 状态。
- 每个工作台卡片增加“查看全部”链接，跳转到对应模块页，形成“总览 → 侧边栏模块”的闭环。
- 侧边栏保持一级导航，折叠后保留 icon；当前页高亮已有，继续保留。

## 三、实施步骤

1. 新增 `PageHeader`、`PaginationBar` 组件与测试；
2. 接入任务/队列/计划/异常/记录 5 个页面；
3. 工作台卡片增加跳转、调整信息密度；
4. dashboard 测试与构建、启动验证；
5. 提交（本地 main，未 push）。
