# BUG-001 剧变剧目被识别为番茄流程

**发现时间**：2026-08-31
**严重程度**：高（影响剧变剧目的正常自动化）

## 现象

剧目表中平台列为"剧变"的剧目（例：悍妇儿媳掌全局），在系统中显示为"提取番茄链接"状态，说明系统将其当作番茄剧目走了番茄链接提取流程。

## 预期行为

- 平台为"剧变"的剧目 → 直接读取剧表中 I/J/K 列链接 → 不进入番茄平台提取
- 平台为"番茄"的剧目 → 进入番茄链接提取流程

## 待排查原因

### 嫌疑 1：飞书表列索引错位
`sheet_parser.py` 中 `_PLATFORM_COLUMN = 7`（H 列）。
如果实际表格中平台列不在 H 列，会读到错误的值。

需要确认：当前飞书剧目表各列的实际位置。

### 嫌疑 2：平台名称映射不精确
`_PLATFORM_NAMES = {"番茄": "TOMATO", "剧变": "JUBIAN"}` 是精确匹配。
如果单元格中有空格、换行、不可见字符，`.strip()` 可能无法完全处理。

### 嫌疑 3：前端展示问题
"提取番茄链接"可能只是 `LINK_EXTRACTION` 阶段的前端统一文案，
实际上后台逻辑对 JUBIAN 平台是正确的（只读 source_links）。
需要确认后台实际执行路径。

### 嫌疑 4：导入流程问题
从公用表导入到私有表时，平台字段可能没有正确传递。

### 嫌疑 5：前端阶段文案不区分平台
后端 `LINK_EXTRACTION` 阶段在前端可能统一显示为"提取番茄链接"，
但实际上 JUBIAN 平台走的是只读 source_links 的正确路径。
需要确认后台日志中该任务的实际执行分支。

## 已发现的相关问题

1. **测试覆盖缺口**：`test_sheet_parser.py` 中平台值直接写 "TOMATO"/"JUBIAN"（英文），
   没有测试中文 "番茄"/"剧变" → 英文的映射路径。实际真实表中是中文。
2. **end_type 未从表中读取**：`DramaTask.end_type` 默认值为 `NATIVE`，
   sheet_parser 完全没有读取端类型列（"原生"/"小程序"）。

## 验证方法

1. 打印/查看该任务的 `task.platform` 值，确认是否为 `JUBIAN`
2. 如果是 `JUBIAN`，检查 `TaskPreparationService._resolve_links` 的分支走向
3. 如果不是 `JUBIAN`，检查 sheet_parser 的列解析是否正确

## 修复计划

纳入 Native V2 开发计划，在 Phase 5 前优先排查并修复。
修复后补充对应单元测试，确保不同平台的分流逻辑有测试覆盖。
