1. 总体目标与最终流程

将端原生前置流程升级成稳定的自动化生产链，解决两个核心问题：

  • 链接经常缺失、DOM 抓取不稳定
  • 每天仍需要人工搭建链接，效率低
剧目表
  ↓
DramaTask
  ↓
等待可执行时间
  ↓
确认正确剧目
  ↓
查询已有推广链接 (API → Network → DOM)
  ↓
自动创建缺失链接 (CreateSafetyGuard)
  ↓
验证 IAA / 2.9 / 9.9 (PromotionMatcher + Validator)
  ↓
获取 album_id (DramaResourceService)
  ↓
完成 Native 必要配置
  ↓
冻结准备结果 (NativePreparationSnapshot)
  ↓
NATIVE_PREPARED

最终要求：正常任务无需人工搭链接，只有异常进入 MANUAL_REVIEW。

2.2 Provider 优先级

API          ← Primary（真实接口，最可靠）
  ↓ fallback
Network      ← 从 XHR/fetch 响应解析
  ↓ fallback
DOM          ← 最后兜底（SimpleDomFallback）
  ↓ fallback
Manual       ← 人工确认

2.3 核心原则

Workflow 不负责点击页面，只负责确保业务 Asset 已存在并验证通过（ensure_promotion() 而非 click_create()）。

API / Network / DOM / 页面点击 / Selector 全部属于 Adapter / Provider 层，Workflow 只编排业务结果。

3. 安全红线

绝不违反的 6 条规则
  1. 不拿错剧：external_drama_id 优先匹配，剧名不匹配的 external_id 候选不选中
  2. 不拿错链接：URL_MISMATCH 是 Critical mismatch，Shadow 验收必须为 0
  3. 不拿错档位：IAA / 2.9 / 9.9 独立匹配，不混淆
  4. 不重复创建：Create 后必须 Requery，不信任 Create 返回值，绝不连续 Create 两次
  5. 多候选不自动猜：>1 条 → AMBIGUOUS → MANUAL_REVIEW，绝不自动取第一条
  6. 未验证资产不冻结：link_set 只含 acquisition_status=VALIDATED + verification_status=VALIDATED 的资产

链接状态明确化

状态含义是否继续生产
FOUND找到并验证通过是
EXPECTED_ABSENT该档位本不应存在是
NOT_FOUND查不到视情况
ACQUISITION_FAILED采集失败否
AMBIGUOUS多个候选否 → 人工
RESULT_UNCERTAIN创建后无法确认否 → 人工
VALIDATION_FAILED验证不通过否 → 人工

4. Phase 5–15 逐阶段详解

5 Network Discovery + Network Acquisition

通过 Playwright 监听 XHR/fetch 响应，识别番茄平台真实接口，并解析为 PromotionAsset Candidate。

核心组件

  • NetworkListener — 挂载到 Playwright Page，监听 response 事件，域名/内容过滤，Header 脱敏
  • TomatoResponseParser — 启发式字段匹配，支持 snake_case / camelCase，自动分类 IAA/2.9/9.9
  • NetworkDiscoveryProvider — 包装 Legacy，同步监听网络，附加 discovery 诊断
  • NetworkProvider — 从捕获的响应中生成 PromotionAsset Candidate，一次读取整部剧

安全规则

  • 不猜接口，只从真实捕获的响应中解析
  • 不保存 Cookie / Token / Authorization
  • 保存脱敏业务 Response 用于分析
6 精确匹配 — PromotionMatcher

从多个 Candidate 中精确匹配出唯一正确的推广资产。

6 级置信度（从高到低）

置信度标识说明
60EXTERNAL_ID外部剧目 ID 匹配
50PROMOTION_ID推广 ID 匹配
40TEMPLATE_ID模板 ID 匹配
30CONFIRMED_MATCH人工确认的剧目匹配
20EXACT_NAME精确剧名匹配
10FUZZY_NAME模糊剧名（不能直接进入生产）

模糊剧名匹配即使唯一也返回 AMBIGUOUS，必须人工确认后才能进入生产。

7 Shadow Mode — Legacy vs V2 对比

SHADOW 模式下 Legacy DOM 走生产，Network V2 只观察，对比并记录差异。

三种运行模式

模式行为
LEGACY只用 Legacy DOM（当前生产模式）
SHADOWLegacy 走生产 + Network 只观察对比
V2只用 Network（未来生产模式）

四种差异类型

差异类型Critical说明
LEGACY_MISSING_V2_FOUND否Legacy 漏链接，V2 找到了
LEGACY_FOUND_V2_MISSING否Legacy 有，V2 没有
URL_MISMATCH是同档位但 URL 不同
AMBIGUOUS否V2 返回歧义结果

验收标准：Critical mismatch = 0 即 is_passing = True

8 API + 自动建链 — CreateSafetyGuard + FallbackChain

CreateSafetyGuard — 创建安全流程

Query → 已有 → 复用 (REUSED)
  ↓ 不存在
Create → 发送创建请求
  ↓ 无论返回什么
Requery → 重新查询确认
  ↓
Validate → 验证通过
  ↓
CREATED                    多个 → AMBIGUOUS
                              0个/验证失败 → UNCERTAIN → MANUAL_REVIEW

安全红线：Create 后必须 Requery，不信任 Create 返回值。绝不连续 Create 两次。

FallbackChainProvider — Provider 优先级链

  • API 成功 → 不降级
  • API 返回 COMPLETE → 停止链
  • API 部分成功 → Network 补充缺失档位
  • 全部失败 → NOT_FOUND
  • 同档位不重复选择（优先级高的先选）

ApiProvider — 真实接口 Provider

通过 TomatoApiClient 协议查询和创建，对每个档位独立执行 CreateSafetyGuard。

9 V2 正式上线 — V2AcquisitionPipeline

完整编排 V2 管线：Provider → Validator → 冻结 link_set。

V2ProviderFactory.build(mode=V2)
  → FallbackChainProvider([API, Network, DOM])
  ↓
V2AcquisitionPipeline.run(task)
  → Provider.acquire → Validator.validate → Freeze link_set
  ↓
READY           全部档位冻结成功
PARTIAL        部分冻结成功
MANUAL_REVIEW   有歧义/验证失败
FAILED          全部缺失

PipelineResult 输出

  • status: READY / PARTIAL / MANUAL_REVIEW / FAILED
  • link_set: 冻结的 {link_type: promotion_url} 快照
  • missing: {link_type: reason} 缺失详情
  • per_type: {link_type: FOUND/NOT_FOUND/...} 逐档位状态
  • diagnostics: 完整诊断摘要
10 album_id 独立化 — DramaResource

独立管理 album_id，供 Native 和 MiniProgram 复用，不重复查询。

已有 → Reuse
没有 → Query
  唯一结果 → Save
  多个结果 → AMBIGUOUS → MANUAL_REVIEW

DramaResource 保存 drama_name、external_drama_id、album_id、status，是未来 Native / MiniProgram 唯一共享的业务数据。

12 Resume + Idempotency

断点恢复：检查已完成的步骤，只执行未完成的部分。所有有副作用的操作统一 ensure_xxx() 语义。

2.9 Promotion    ✅
9.9 Promotion    ✅
album_id         ✅
Native Config    ❌
                    ↓ 重新运行
只继续 Native Config（不重新创建已完成的推广资产）
13 清理旧 Runtime — DOM 降级为兜底

V2 完整跑通后，DOM 从主路径降级为最后兜底。

  • SimpleDomFallback 包装 LegacyDomProvider，标记为兜底
  • V2ProviderFactory V2 模式用 SimpleDomFallback 替代裸 Legacy
  • 清理旧主流程中的 DOM-first 获取、多 Candidate 取第一条、Clipboard 未验证即成功
14 Manual Review — 人工审核

只允许真正无法自动判断的问题进入人工。

  • 同名剧 / 多个版本 / 多个 Promotion
  • 平台验证码 / 登录失效
  • 创建结果无法确认 / 关键数据验证失败

人工确认后保存结果 → Resume，不重新执行整个任务。

ManualReviewService.resolve(task, action)
  ├─ confirm → is_resolved=True → 回到 WAITING_TIME → Resume
  └─ reject  → is_resolved=False → 保持 MANUAL_REVIEW
15 NativePreparationSnapshot — 冻结快照

进入 NATIVE_PREPARED 前必须生成冻结快照，是后续 Auto Plan 唯一允许消费的输入。

字段说明
task_id任务 ID
drama_name剧名
external_drama_id外部剧目 ID
link_set冻结的 {IAA/2.9/9.9: url}
album_id投放系统剧目 ID
per_type逐档位状态
statusNATIVE_PREPARED
prepared_at冻结时间

快照是深拷贝独立副本，修改原 task 不影响快照。后续 Auto Plan 只读此快照，禁止重新搜索/猜链接。

6. 完整数据流

剧目表 → DramaTask
  │
  ▼
NativeWorkflowService.execute(task)
  │
  ├─ ensure_promotions()
  │  │
  │  └─ V2ProviderFactory.build(mode=V2)
  │     → FallbackChainProvider([
  │         ApiProvider
  │           └─ CreateSafetyGuard: Query→Create→Requery→Validate
  │         NetworkProvider
  │           └─ PromotionMatcher: 6级置信度精确匹配
  │         SimpleDomFallback
  │           └─ Legacy DOM 兜底
  │       ])
  │  ↓
  │  V2AcquisitionPipeline.run(task)
  │  → Provider.acquire → PromotionAssetValidator.validate → Freeze link_set
  │  → READY / PARTIAL / MANUAL_REVIEW / FAILED
  │
  ├─ ensure_album_id()
  │  └─ DramaResourceService.ensure_album_id(task)
  │     → 已有→Reuse / 没有→Query / 多个→AMBIGUOUS
  │
  ├─ validate_preparation() → freeze_preparation()
  │  └─ SnapshotService.generate(task, pipeline_result)
  │     → NativePreparationSnapshot (深拷贝，后续只读)
  │
  └─ mark_native_prepared()
     → NATIVE_PREPARED

异常路径：
  推广失败/歧义 → MANUAL_REVIEW
  → ManualReviewService.resolve() → 确认后 Resume
  → ResumeService.resume() 从断点继续
